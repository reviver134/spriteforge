# L2.7: the Sound Director

The user asked for "a sound director in the game that gives appropriate sound to the game: a
slime jumps and lands with a splash, moves with a water rumble, bullets firing, boxes or walls
breaking, points collected; and make it editable for the user."

## How it works

| piece | where | what |
| --- | --- | --- |
| Sound Director | `agents/roles/sound-director.md` | role prompt (Muse Spark, `llm.reasoning.sounds: low`) |
| schema, presets, fit, checks | `game/sounds.py` | `SoundBrief` (model) -> `SoundSet` (layers, what the SDK plays and the editor edits) |
| synth and moments | `game/sdk/sfsound.js` | Web Audio synth (`window.SFSynth`), hooks `sf.event` and `sf.fx`, the `move` loop, M to mute, `sf.soundCount` |
| sound editor | `game/sdk/sounds.html`, `sfsound-editor.js` | in every build; saves to the run or downloads `sounds.js` |
| build | `game/build.py` | `sounds=` writes `sounds.js/.json`, loads `sfsound.js` after `sf.js` |
| gated run | `stages/game.py` | `game/sounds/vS.json/.md`; v1 at G2 approval; refit on a design change; G4 `sound_changes`; editor saves |
| save endpoint | `app/server.py` | `POST /api/runs/<id>/sounds/v<N>` `{sounds: SoundSet}` |
| `game make` | `game/pipeline.py` | `sounds.json/.md` in the output folder; report `sounds` |

**Moments.** A cue plays on the moments in its `on` list:

* SDK effects (`sf.fx`): jump, land, dash, break, kill, pickup, transform, hurt, checkpoint, exit.
  Several cues on one moment are picked by the thing's words (`crate_crate` for the crate,
  `wall_wall` for the wall), as `sf.fx` picks effects.
* SDK events: level_start, respawn, level_complete, win, lose, pause, resume, menu_move,
  menu_select, title, choice.
* `move`: a loop, repeated every `every` seconds while the player moves on the ground (levels as
  data) or moves at all (other games, from `sf.state.x/y`).
* The design's check events. One the SDK already sounds (`crate_open` is a break) joins that
  moment's cue; a cue plays at most once every 3 steps, so an event and its effect in the same
  step sound once.
* The game's own events (e.g. `shoot` for bullets): the Sound Director may add them; the
  Programmer is told to emit `sf.event('shoot')` (assets summary, "Sound events"), and a sound
  revision that adds one sends that instruction with the rebuild.

**Layers.** A cue is 1-4 layers: wave (square, triangle, sine, sawtooth, noise), pitch from
`freq` to `freq_end`, attack/hold/release, delay, volume, optional filter (low/high/band-pass,
`cutoff` to `cutoff_end`, Q) and a wobble (vibrato on a tone, a filter sweep or tremolo on
noise), plus the cue's volume, random pitch variation (`jitter`) and loop interval.

**Locking.** Like the art, a sound set is never regenerated by a model unless asked: each
version is a locked artifact; the editor and G4 feedback make new versions; a revision keeps the
layers of every cue it did not change (so hand edits survive); a design change refits by code
(no model call), adding cues only for new moments.

## Tests

`tests/test_sounds.py`: the offline Sound Director for the slime game (splash, squish, bubble
loop; crate and wall break differently); fit repairs (unknown preset, synonyms, ranges, custom
events, silent moments filled); editor edits clamped and unknown moments flagged; a revision that
changes only what it names and keeps hand edits; refit; build order and editor files; the bot's
level playtest hears the jump, landing, move loop, both breaks and the dash, with `crate_open`
played once by the crate's sound; every preset renders audibly (OfflineAudioContext) and the
editor edits and downloads; M and Settings > Sound; a gated mock run: sounds v1 at G2, the
editor's save through the endpoint (clamped, 422 on a bad body, 404 on an unknown build), G4
"too loud" revising the sound without a rebuild, a later rebuild playing the latest version.
